# Agent Workflow Audit 六週需求驗證規則

這份文件只定義何時可以開始第二個 PR。它不保存詢問信、公司名稱、聯絡人、報價、訪談逐字稿或客戶資料。

## 計時方式

- 起點：Agent Workflow Audit 服務入口合併到 `main` 的 UTC 日期。
- 終點：起點後第 42 天。
- 實際詢問與訪談資料只保存在 maintainer 的私人工作空間，不 commit 到 repository。
- 公開 repository 最多記錄匿名總數與通過／未通過決定。

## 私下記錄哪些欄位

每一筆詢問只在私人紀錄中保存：

1. 詢問來源。
2. 想解決的問題。
3. 現在使用的替代方式。
4. 失敗造成的時間、金錢或工作影響。
5. 可以接受的預算。
6. 希望完成的期限。
7. 沒有成交的原因。

不要在這份文件、GitHub Issue、Discussion、PR 或其他公開檔案填入實際內容。

## 三個門檻怎麼算

### 1. 至少 5 個合格詢問

一個詢問必須同時說清楚以下內容才算合格：

- 有明確使用者。
- 有現行人工流程、Agent prototype 或已在執行的 workflow。
- 有想改善的問題與預期成果。
- 願意討論預算與期限。

只有「想用 AI 做點事情」或只推薦工具、沒有實際流程的訊息不計入。

### 2. 至少 3 次有效需求訪談

一次訪談必須和實際使用者、流程負責人或可以決定預算的人完成，並確認：

- 現行流程真的存在。
- 問題發生時會造成什麼損失。
- 對方如何判斷 Audit 有用。
- 對方是否願意為明確範圍付費，以及不願意時的原因。

只做產品介紹、沒有驗證對方流程的通話不計入。

### 3. 至少 1 次付費證據

以下任一項成立即可：

- 一次 Agent Workflow Audit 已付款。
- 對方以書面確認願意接受明確範圍與價格，但因可記錄的時間、採購或內部批准障礙尚未付款。

「聽起來不錯」或沒有範圍與價格的口頭鼓勵不算付費意願。

## 六週後的決定

只有 `5 個合格詢問／3 次有效訪談／1 次付費證據` 三個門檻全部達成，才建立 PR 2，把真實經驗整理成開發者路線與 Capstone 的「作品到付費 Pilot」檢查卡。

如果任何門檻沒有達成：

1. 只調整目標客群、問題描述或 Audit 交付物。
2. 再跑一輪有明確起訖日的需求驗證。
3. 不開始 SaaS、billing、會員、認證或 marketplace 開發。
4. 不把沒有付費證據的想法寫成已驗證教材。

## 案例與公開結果

- 客戶案例必須先取得書面同意。
- 公開內容只保留問題、方法、可量化改善與限制。
- 公司、個人、客戶與機密資料必須移除。
- 六週結束時可以公開匿名總數與 go／revise 決定，但不能公開私人紀錄。
